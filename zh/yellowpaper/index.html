Ethercoin Technical Yellowpaper — Ethercoin 技术黄皮书

去中心化 AI 计算与蒸馏协议

Version 2.0 — 2026年6月 · 代币: ETHER · 白皮书

1. 引言

本黄皮书定义了 Ethercoin 去中心化 AI 计算网络的技术架构。该网络提供了一个去中心化、抗审查、可验证的通用 AI 推理、模型优化和知识蒸馏执行环境。

核心挑战：如何在不信任任何单一方的情况下精确衡量异构"有用计算"，同时系统性防止作弊。本文档详细阐述了 EtherFLOP 衡量标准、分层验证框架、反作弊算法以及完整的蒸馏协议规范。

2. 系统概述

3. EtherFLOP：衡量系统

3.1 单位定义

EtherFLOP（EFLOP） = 1015 次浮点运算。基准模型：一个标准化的冻结 LLaMA-7B 执行一次前向传播（输入 = 1 个 token，输出 logits = 词汇表大小）。理论 FLOPs = 2 × 参数数量 × 序列长度，公开计算且可独立审计。

3.2 任务工作量估算

对于任何提交的模型 M（由 IPFS CID 标识）和输入形状（batch, seq_len），链下调度器解析计算图并计算理论 FLOPs 值 Ftheoretical。该值由预言机委员会（多个质押 ETHER 的独立节点，BFT 共识）签名，并写入任务合约的 expectedEFLOPS 字段。估算误差必须保持在 ±5% 以内，由社区治理校准。

3.3 供应端证明

节点提交 WorkProof：

WorkProof {
    outputCID: bytes32,
    anchorHashes: bytes32[],  // Optimistic mode: random layer activations
    zkProof: bytes,           // ZK mode: zk-SNARK proof
    teeAttestation: bytes     // TEE mode: remote attestation report
}

3.3.1 乐观验证

随机锚点生成：链上 VRF 在任务创建时生成 k 个随机层索引（l1, ..., lk）及相应的随机输入种子。节点提供这些层的激活哈希值。

验证者抽查：随机选择的验证者从 IPFS 下载模型和输入，重新执行指定层并比较哈希值。如果所有 k 个锚点都匹配，则计算被接受。跳过 f 比例计算的作弊者，其被检测概率为 1 - (1-f)k，随 k 呈指数级趋近于 1。

二元挑战：如果验证者发现锚点不匹配，则发起链上交互式二元游戏。双方迭代地将争议缩小到单个操作。合约以恒定 gas 成本执行该单步操作，判定获胜者。

3.3.2 零知识证明

节点使用 ZK 编译器（例如 zkLLVM 或自定义电路）将模型推理转换为 R1CS/AIR 约束系统，并生成 zk-SNARK 证明。合约验证证明的有效性。电路大小 C 与理论 FLOPs 具有固定的比例关系（系数 α 由治理设定）。已验证 EFLOPs = C × α。

3.3.3 TEE 证明

节点在 Intel SGX / AMD SEV 安全区内执行推理，生成包含代码哈希、输入哈希、输出哈希和硬件可信执行时间的远程证明报告。合约根据 Intel/AMD 链上公钥验证报告签名，并使用 TEE 内 GPU 性能模型将执行时间转换为等效 EFLOPs。

3.4 需求端衡量

用户支付 = expectedEFLOPS × 当前市场 EFLOP 价格（通过链上订单簿发现）。挑战质押金额与任务价值成比例。如果仲裁判定挑战无效，质押金将被罚没并归节点所有。

4. 计算市场协议

4.1 节点注册

调用 NodeRegistry.register(nodeType, hardwareProof, stakeAmount)。硬件证明通过 TEE 自我证明报告或第三方基准测试结果提交；伪证将被罚没。链上声誉根据任务完成率、正确率和平均响应时间计算，影响任务分配权重。

4.2 任务生命周期（推理）

  1. 提交：用户调用 TaskMarket.createTask(modelCID, inputCID, expectedEFLOPS, verificationMode, reward)，锁定 ETHER。
  2. 匹配：链下匹配引擎监听事件，根据声誉和定价提名节点集。合约使用 VRF 选择节点，防止定向合谋。
  3. 执行并提交：节点生成 WorkProof 并提交。
  4. 验证：验证遵循所选模式。在乐观模式下，验证者可在挑战期内提交挑战。
  5. 结算：挑战期过后（ZK/TEE 模式为立即结算），分发奖励，并对作弊行为触发惩罚。

4.3 反作弊矩阵

攻击类型防御手段实现方式
女巫攻击质押 + 声誉新节点任务上限 = f(质押量, 历史声誉)
虚假计算分层验证乐观锚点 / ZK 证明 / TEE 证明
模型欺骗权重哈希白名单 + 锚点检查modelCID 必须在链上；不同模型架构产生不同的激活分布
买卖双方合谋随机验证者选择 + 验证者质押VRF 选择验证者；验证者质押与矿工质押相匹配
梯度欺诈检查点评估 + 优化器状态哈希验证者在测试集上运行推理；无指标提升 = 罚没
蒸馏伪造独立路径复现 + 代理签名验证者通过不同代理路径获取响应；语义相似度比较
代理篡改路径签名 + 异常检测每跳对载荷哈希链签名；异常惩罚中间跳

5. 推理与优化技术规范

5.1 推理 ABI

标准 EIABI：

{
  "model_cid": "bafy...",
  "input": {"prompt": "...", "max_tokens": 256, "temperature": 0.7},
  "expectedEFLOPS": 1500,
  "verificationMode": "optimistic" | "zk" | "tee"
}

5.2 优化任务

任务输出优化后的模型 CID 及工作证明（包括量化误差报告或微调权重增量哈希）。验证者重现优化过程并比较结果。

6. 蒸馏协议

6.1 设计目标

从闭源 API 中提取知识，流程可验证且抗审查。工作量以"有效数据点"衡量。

6.2 核心合约：DistillationMarket

  • createTask(targetModel, reward, promptTreeRoot)：创建者锁定 ETHER。
  • claimBatch(taskID, stake)：矿工质押 ETHER，认领一个提示批次。
  • submitBatch(taskID, batchID, dataCID, responseHash, proxyPathSigs)：提交结果和代理路由签名。
  • challengeBatch(taskID, batchID, proof)：验证者提交挑战。
  • finalizeBatch(taskID, batchID)：结算。

6.3 提示分发

DAO 维护一个主题树，其根存储在合约中。矿工通过 VRF 接收叶子哈希和 Merkle 路径，并从 IPFS 链下获取明文提示。

6.4 代理网络与路径签名

代理节点注册公钥并质押 ETHER。矿工构建洋葱加密的多跳路径；每跳解密下一跳地址并转发。响应携带路径签名链：SignNk(...SignN2(SignN1(responseHash)))。合约验证路径完整性。

6.5 验证与衡量

语义验证：验证者通过完全不同的代理路径获取相同提示的响应，并使用公共嵌入模型计算余弦相似度。超过阈值 θ（例如 0.92）的相似度计为一个有效数据点。

衡量：矿工奖励 = 已验证数据点 × 单位数据点价格。无效数据点奖励为零并降低声誉。

6.6 仲裁

争议由仲裁合约处理。多个仲裁人（高质押验证者）独立判断并投票。多数决定获胜。

7. 分布式训练集成

训练任务纳入 EtherFLOP 框架。用户指定基础模型 CID、数据集 CID 和训练配置。expectedEFLOPS 由总优化步数 × 每步 FLOPs 计算得出。

节点提交周期性检查点哈希值和梯度范数中间值。验证者重新运行随机检查点以确认真实执行。训练完成后，验证者在公开测试集上评估模型性能。未达到改进目标将导致部分质押罚没。

8. 安全与隐私

  • 衡量安全：锚点模型和预言机委员会使 EFLOPs 不可操纵。ZK 证明提供无需信任的衡量。
  • 女巫防御：高质押要求和随声誉扩展的任务限额。
  • 隐私：推理输入在 TEE 内部解密。蒸馏提示通过代理网络进行洋葱加密。
  • 抗审查：所有合约不可升级或由 DAO 控制。代理网络使用 libp2p noise 加密实现去中心化。

10. 结论

Ethercoin 的技术架构以有用计算的可验证衡量为核心。通过 EtherFLOP 单位、分层证明、随机锚点、ZK/TEE 验证以及全面的反作弊矩阵，该网络能够在不可信环境中实现公平安全的 AI 计算交易。蒸馏协议将此计算市场扩展为知识解放的工具。
