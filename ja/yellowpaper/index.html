Ethercoin Technical Yellowpaper — イーサコイン技術イエローペーパー

分散型AIコンピューティング＆蒸留プロトコル

Version 2.0 — June 2026 · Token: ETHER · ホワイトペーパー

1. はじめに

本書（イエローペーパー）は、Ethercoinの分散型AIコンピューティングネットワークの技術アーキテクチャを定義するものである。このネットワークは、分散型で検閲耐性があり、検証可能な実行環境を、汎用的なAI推論、モデル最適化、および知識蒸留のために提供する。

中核的な課題：いかなる単一の当事者も信頼することなく、異種の「有用な計算」を正確に測定し、かつ不正を体系的に防止する方法。本ドキュメントでは、EtherFLOP測定基準、階層型検証フレームワーク、アンチチートアルゴリズム、および完全な蒸留プロトコル仕様について詳述する。

3. EtherFLOP：測定システム

3.1 単位定義

EtherFLOP（EFLOP） = 1015回の浮動小数点演算。ベースラインモデル：標準化されたフリーズ状態のLLaMA-7Bによる1回のフォワードパス（入力 = 1トークン、出力ロジット = 語彙サイズ）。理論FLOPs = 2 × パラメータ数 × シーケンス長。公開計算され、独立して監査可能である。

3.2 タスクワークロード推定

任意の提出モデルM（IPFS CIDで識別）と入力形状（バッチ、シーケンス長）について、オフチェーンのスケジューラが計算グラフを解析し、理論FLOPs値Ftheoreticalを算出する。この値はオラクル委員会（ETHERをステークする複数の独立ノード、BFTコンセンサス）によって署名され、タスクコントラクトのexpectedEFLOPSフィールドに書き込まれる。推定誤差は±5%以内に収める必要があり、コミュニティガバナンスによって調整される。

3.3 供給側の証明

ノードはWorkProofを提出する：

WorkProof {
    outputCID: bytes32,
    anchorHashes: bytes32[],  // Optimistic mode: random layer activations
    zkProof: bytes,           // ZK mode: zk-SNARK proof
    teeAttestation: bytes     // TEE mode: remote attestation report
}

3.3.1 オプティミスティック検証

ランダムアンカー生成：タスク作成時に、オンチェーンVRFがk個のランダムなレイヤーインデックス（l1, ..., lk）と対応するランダム入力シードを生成する。ノードはこれらのレイヤーの活性化ハッシュを提供する。

検証者スポットチェック：ランダムに選ばれた検証者がIPFSからモデルと入力をダウンロードし、指定されたレイヤーを再実行してハッシュを比較する。すべてのk個のアンカーが一致した場合、計算は受理される。計算の一部fをスキップした不正者に対する検出確率は1 - (1-f)kであり、kに応じて指数的に1に収束する。

バイナリチャレンジ：検証者がアンカーの不一致を検出した場合、オンチェーン上でインタラクティブなバイナリゲームを開始する。両当事者は段階的に紛争を単一の演算に絞り込む。コントラクトはその単一ステップを一定のガスコストで実行し、勝者を決定する。

3.3.2 ゼロ知識証明

ノードはZKコンパイラ（例：zkLLVMまたはカスタム回路）を使用して、モデル推論をR1CS/AIR制約システムに変換し、zk-SNARK証明を生成する。コントラクトは証明の有効性を検証する。回路サイズCは理論FLOPsと固定的な比例関係を持つ（係数αはガバナンスで設定）。検証済みEFLOPs = C × α。

3.3.3 TEEアテステーション

ノードはIntel SGX / AMD SEVエンクレーブ内で推論を実行し、コードハッシュ、入力ハッシュ、出力ハッシュ、およびハードウェア信頼の実行時間を含むリモートアテステーションレポートを生成する。コントラクトはIntel/AMDのオンチェーン公開鍵に対してレポートの署名を検証し、GPU-in-TEEパフォーマンスモデルを使用して実行時間を等価なEFLOPsに変換する。

3.4 需要側の測定

ユーザーの支払い = expectedEFLOPS × 現在の市場EFLOP価格（オンチェーンオーダーブックで発見される）。チャレンジのステークはタスク価値に比例する。仲裁によりチャレンジが無効と判断された場合、ステークは没収されノードに与えられる。

4. コンピューティングマーケットプロトコル

4.1 ノード登録

NodeRegistry.register(nodeType, hardwareProof, stakeAmount)を呼び出す。ハードウェア証明はTEE自己アテステーションレポートまたは第三者ベンチマーク結果により提出され、偽証はスラッシュ対象となる。オンチェーン上のレピュテーションは、タスク完了率、正確性比率、平均応答時間から計算され、タスク割り当ての重みに影響する。

4.2 タスクライフサイクル（推論）

  1. 提出：ユーザーがTaskMarket.createTask(modelCID, inputCID, expectedEFLOPS, verificationMode, reward)を呼び出し、ETHERをロックする。
  2. マッチング：オフチェーンのマッチングエンジンがイベントをリッスンし、レピュテーションと価格に基づいてノードセットを指名する。コントラクトはVRFを使用してノードを選択し、標的型の結託を防ぐ。
  3. 実行と提出：ノードがWorkProofを生成し、提出する。
  4. 検証：選択されたモードに従って検証が行われる。オプティミスティックモードでは、検証者はチャレンジ期間中にチャレンジを提出できる。
  5. 決済：チャレンジ期間後（ZK/TEEの場合は即時）、報酬が分配され、不正が検出された場合はペナルティが発動される。

5. 推論＆最適化技術仕様

5.1 推論ABI

標準EIABI：

{
  "model_cid": "bafy...",
  "input": {"prompt": "...", "max_tokens": 256, "temperature": 0.7},
  "expectedEFLOPS": 1500,
  "verificationMode": "optimistic" | "zk" | "tee"
}

5.2 最適化タスク

タスクは最適化されたモデルCIDと作業証明（量子化誤差レポートやファインチューニングされた重みの差分ハッシュを含む）を出力する。検証者は最適化を再現し、結果を比較する。

6. 蒸留プロトコル

6.1 設計目標

クローズドソースAPIから知識を抽出し、検証可能で検閲耐性のあるプロセスを実現する。ワークロードは「有効データポイント」で測定される。

6.2 中核コントラクト：DistillationMarket

  • createTask(targetModel, reward, promptTreeRoot)：作成者がETHERをロックする。
  • claimBatch(taskID, stake)：マイナーがETHERをステークし、プロンプトバッチを請求する。
  • submitBatch(taskID, batchID, dataCID, responseHash, proxyPathSigs)：結果とプロキシ経路署名を提出する。
  • challengeBatch(taskID, batchID, proof)：検証者がチャレンジを提出する。
  • finalizeBatch(taskID, batchID)：決済。

6.3 プロンプト配布

DAOはトピックツリーを管理し、そのルートはコントラクトに保存される。マイナーはVRFを介してリーフハッシュとマークルパスを受け取り、IPFSからオフチェーンで平文のプロンプトを取得する。

6.4 プロキシネットワーク＆経路署名

プロキシノードは公開鍵を登録し、ETHERをステークする。マイナーはオニオン暗号化されたマルチホップ経路を構築し、各ホップが次のアドレスを復号して転送する。レスポンスには経路署名チェーンが付与される：SignNk(...SignN2(SignN1(responseHash)))。コントラクトは経路の整合性を検証する。

6.5 検証と測定

意味的検証：検証者は、完全に異なるプロキシ経路を通じて同一のプロンプトに対するレスポンスを取得し、公開埋め込みモデルを使用してコサイン類似度を計算する。閾値θ（例：0.92）以上の類似度は、有効なデータポイントとしてカウントされる。

測定：マイナーの報酬 = 検証済みデータポイント数 × 単位データポイント価格。無効なデータポイントは報酬ゼロとなり、レピュテーションが低下する。

6.6 仲裁

紛争は仲裁コントラクトによって処理される。複数の仲裁者（高ステークの検証者）が独立して判断し投票する。多数決の決定が優先される。

7. 分散型トレーニング統合

トレーニングタスクはEtherFLOPフレームワークに組み込まれる。ユーザーはベースモデルCID、データセットCID、およびトレーニング設定を指定する。expectedEFLOPSは、最適化ステップ数合計 × ステップあたりFLOPsから計算される。

ノードは定期的にチェックポイントハッシュと勾配ノルムの中間値を提出する。検証者はランダムなチェックポイントを再実行し、実際の実行を確認する。トレーニング後、検証者は公開テストセット上でモデルのパフォーマンスを評価する。改善目標に達しなかった場合、部分的なステークのスラッシングが行われる。

8. セキュリティとプライバシー

  • 測定のセキュリティ：アンカーモデルとオラクル委員会により、EFLOPsは操作不可能となる。ZK証明はトラストレスの測定を提供する。
  • Sybil防御：高額なステーキングと、レピュテーションに応じてスケールするタスク制限。
  • プライバシー：推論の入力はTEE内部で復号される。蒸留プロンプトはプロキシネットワークを通じてオニオン暗号化される。
  • 検閲耐性：すべてのコントラクトはアップグレード不可またはDAO制御である。プロキシネットワークはlibp2pノイズ暗号化により分散化されている。

10. 結論

Ethercoinの技術アーキテクチャは、有用な計算の検証可能な測定を中心に据えている。EtherFLOP単位、階層型証明、ランダムアンカー、ZK/TEE検証、および包括的なアンチチートマトリックスを通じて、ネットワークは信頼できない環境でもAIコンピューティングの公正で安全な取引を可能にする。蒸留プロトコルは、このコンピューティングマーケットを知識解放のためのツールへと拡張する。
