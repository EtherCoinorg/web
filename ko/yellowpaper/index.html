Ethercoin Technical Yellowpaper — 기술 사양서

분산형 AI 컴퓨팅 및 증류 프로토콜

Version 2.0 — June 2026 · Token: ETHER · 백서

1. 소개

본 황서는 Ethercoin 분산형 AI 컴퓨팅 네트워크의 기술 아키텍처를 정의합니다. 이 네트워크는 일반 AI 추론, 모델 최적화, 지식 증류를 위한 분산형이고 검열에 저항하며 검증 가능한 실행 환경을 제공합니다.

핵심 과제: 어떻게 어느 한 당사자도 신뢰하지 않으면서 이질적인 "유용한 연산"을 정밀하게 측정하고, 체계적으로 부정행위를 방지할 것인가. 본 문서는 EtherFLOP 측정 표준, 계층형 검증 프레임워크, 부정행위 방지 알고리즘, 그리고 완전한 증류 프로토콜 사양을 상세히 설명합니다.

2. 시스템 개요

Ethercoin은 계층형 아키텍처를 사용합니다:

+---------------------------------------------------+
|              Application Layer                     |
|   +-----------+ +------------+ +----------------+ |
|   | Inference | |Optimization| |  Distillation   | |
|   +-----------+ +------------+ +----------------+ |
+---------------------------------------------------+
|         Market & Consensus Layer                   |
|   +--------------------------------------------+  |
|   |Task Matching|Verification|Settlement/Slashing| |
|   +--------------------------------------------+  |
+---------------------------------------------------+
|            Execution Layer                         |
|   +----------+ +----------+ +------------------+  |
|   |GPU Nodes | |Proxies   |  |  Verifiers       |  |
|   +----------+ +----------+ +------------------+  |
+---------------------------------------------------+
|         DA & Storage Layer                         |
|         IPFS / Filecoin / On-chain Events          |
+---------------------------------------------------+

온체인: Ethercoin 네이티브 체인(EVM 호환)의 스마트 계약.

오프체인: 노드 클라이언트, 스케줄링 서비스, 분산 프록시 네트워크, P2P로 통신하는 GPU 실행 환경.

3. EtherFLOP: 측정 시스템

3.1 단위 정의

EtherFLOP (EFLOP) = 1015회의 부동소수점 연산. 기준 모델: 표준화된 고정 LLaMA-7B가 한 번의 순전파(입력 = 1 토큰, 출력 로짓 = 어휘 크기)를 실행합니다. 이론적 FLOPs = 2 × 매개변수 수 × 시퀀스 길이로, 공개적으로 계산되고 독립적으로 감사 가능합니다.

3.2 작업 부하 추정

제출된 모델 M(IPFS CID로 식별)과 입력 형태(batch, seq_len)에 대해, 오프체인 스케줄러가 연산 그래프를 파싱하고 이론적 FLOPs 값 Ftheoretical을 계산합니다. 이 값은 오라클 위원회(ETHER를 스테이킹하고 BFT 합의를 사용하는 여러 독립 노드)에 의해 서명되어 작업 계약의 expectedEFLOPS 필드에 기록됩니다. 추정 오차는 ±5% 이내여야 하며, 커뮤니티 거버넌스로 보정됩니다.

3.3 공급 측 증명

노드는 WorkProof를 제출합니다:

WorkProof {
    outputCID: bytes32,
    anchorHashes: bytes32[],  // Optimistic mode: random layer activations
    zkProof: bytes,           // ZK mode: zk-SNARK proof
    teeAttestation: bytes     // TEE mode: remote attestation report
}

3.3.1 낙관적 검증

랜덤 앵커 생성: 온체인 VRF가 작업 생성 시 k개의 무작위 레이어 인덱스(l1, ..., lk)와 해당하는 무작위 입력 시드를 생성합니다. 노드는 이 레이어들에 대한 활성화 해시를 제공합니다.

검증자 스팟 체크: 무작위로 선정된 검증자가 IPFS에서 모델과 입력을 다운로드하고, 지정된 레이어를 재실행하여 해시를 비교합니다. 모든 k개의 앵커가 일치하면 연산이 승인됩니다. 연산의 일부 f를 건너뛴 부정행위자의 탐지 확률은 1 - (1-f)k이며, k에 따라 지수적으로 1에 수렴합니다.

이진 챌린지: 검증자가 앵커 불일치를 발견하면, 온체인 대화형 이진 게임을 시작합니다. 양 당사자는 분쟁을 반복적으로 단일 연산으로 좁혀 나갑니다. 계약은 해당 단일 단계를 일정한 가스 비용으로 실행하여 승자를 결정합니다.

3.3.2 영지식 증명

노드는 ZK 컴파일러(예: zkLLVM 또는 커스텀 회로)를 사용하여 모델 추론을 R1CS/AIR 제약 시스템으로 변환하고 zk-SNARK 증명을 생성합니다. 계약은 증명의 유효성을 검증합니다. 회로 크기 C는 이론적 FLOPs와 고정된 비례 관계를 가집니다(계수 α는 거버넌스로 설정). 검증된 EFLOPs = C × α.

3.3.3 TEE 증명

노드는 Intel SGX / AMD SEV 엔클레이브 내에서 추론을 실행하고, 코드 해시, 입력 해시, 출력 해시, 하드웨어 신뢰 실행 시간이 포함된 원격 증명 보고서를 생성합니다. 계약은 Intel/AMD 온체인 공개 키에 대한 보고서 서명을 검증하고, GPU-in-TEE 성능 모델을 사용하여 실행 시간을 동등한 EFLOPs로 변환합니다.

3.4 수요 측 측정

사용자 지불액 = expectedEFLOPS × 현재 시장 EFLOP 가격(온체인 주문장을 통해 발견). 챌린지 지분은 작업 가치에 비례합니다. 중재가 챌린지를 무효로 판정하면, 지분은 노드에 귀속됩니다.

4. 컴퓨팅 마켓 프로토콜

4.1 노드 등록

NodeRegistry.register(nodeType, hardwareProof, stakeAmount)를 호출합니다. 하드웨어 증명은 TEE 자체 증명 보고서 또는 제3자 벤치마크 결과를 통해 제출되며, 위증 시 슬래싱됩니다. 온체인 평판은 작업 완료율, 정확성 비율, 평균 응답 시간으로 계산되어 작업 할당 가중치에 영향을 줍니다.

4.2 작업 수명 주기 (추론)

  1. 제출: 사용자가 TaskMarket.createTask(modelCID, inputCID, expectedEFLOPS, verificationMode, reward)를 호출하여 ETHER를 잠급니다.
  2. 매칭: 오프체인 매칭 엔진이 이벤트를 수신하고, 평판과 가격에 기반하여 노드 세트를 선정합니다. 계약은 VRF를 사용하여 노드를 선택함으로써 표적 담합을 방지합니다.
  3. 실행 및 제출: 노드가 WorkProof를 생성하여 제출합니다.
  4. 검증: 선택된 모드에 따라 검증이 진행됩니다. 낙관적 모드에서는 검증자가 챌린지 기간 동안 이의를 제기할 수 있습니다.
  5. 정산: 챌린지 기간 이후(또는 ZK/TEE의 경우 즉시), 보상이 분배되고 부정행위에 대한 패널티가 실행됩니다.

4.3 부정행위 방지 매트릭스

공격방어구현
시빌(Sybil)지분 + 평판신규 노드 작업 한도 = f(지분, 과거 평판)
가짜 연산계층형 검증낙관적 앵커 / ZK 증명 / TEE 증명
모델 스푸핑가중치 해시 화이트리스트 + 앵커 검사modelCID는 온체인에 있어야 함; 다른 모델 아키텍처는 구별되는 활성화 분포를 생성함
구매자-판매자 담합무작위 검증자 선정 + 검증자 스테이킹VRF가 검증자를 선택; 검증자 지분이 채굴자 지분과 일치
그래디언트 사기체크포인트 평가 + 옵티마이저 상태 해시검증자가 테스트 세트 추론을 실행; 지표 개선 없음 = 슬래싱
증류 위조독립 경로 재현 + 프록시 서명검증자가 다른 프록시 경로를 통해 응답을 획득; 의미적 유사도 비교
프록시 변조경로 서명 + 이상 탐지각 홉이 페이로드 해시 체인에 서명; 불일치 시 중간 홉에 패널티 부과

5. 추론 및 최적화 기술 사양

5.1 추론 ABI

표준 EIABI:

{
  "model_cid": "bafy...",
  "input": {"prompt": "...", "max_tokens": 256, "temperature": 0.7},
  "expectedEFLOPS": 1500,
  "verificationMode": "optimistic" | "zk" | "tee"
}

5.2 최적화 작업

작업은 최적화된 모델 CID와 작업 증명(양자화 오류 보고서 또는 미세 조정된 가중치 델타 해시 포함)을 출력합니다. 검증자는 최적화를 재현하고 결과를 비교합니다.

6. 증류 프로토콜

6.1 설계 목표

검증 가능하고 검열에 저항하는 프로세스로 폐쇄형 API에서 지식을 추출합니다. 작업량은 "유효 데이터 포인트"로 측정됩니다.

6.2 핵심 계약: DistillationMarket

  • createTask(targetModel, reward, promptTreeRoot): 생성자가 ETHER를 잠급니다.
  • claimBatch(taskID, stake): 채굴자가 ETHER를 스테이킹하고 프롬프트 배치를 청구합니다.
  • submitBatch(taskID, batchID, dataCID, responseHash, proxyPathSigs): 결과와 프록시 경로 서명을 제출합니다.
  • challengeBatch(taskID, batchID, proof): 검증자가 이의를 제기합니다.
  • finalizeBatch(taskID, batchID): 정산.

6.3 프롬프트 분배

DAO는 계약에 루트가 저장된 주제 트리를 유지합니다. 채굴자는 VRF를 통해 리프 해시와 머클 경로를 받고, IPFS에서 오프체인으로 평문 프롬프트를 검색합니다.

6.4 프록시 네트워크 및 경로 서명

프록시 노드는 공개 키를 등록하고 ETHER를 스테이킹합니다. 채굴자는 양파 암호화 다중 홉 경로를 구축하고, 각 홉이 다음 주소를 복호화하여 전달합니다. 응답은 경로 서명 체인을 포함합니다: SignNk(...SignN2(SignN1(responseHash))). 계약은 경로 무결성을 검증합니다.

6.5 검증 및 측정

의미적 검증: 검증자는 완전히 다른 프록시 경로를 통해 동일한 프롬프트에 대한 응답을 검색하고, 공개 임베딩 모델을 사용하여 코사인 유사도를 계산합니다. 임계값 θ(예: 0.92) 이상의 유사도는 유효 데이터 포인트로 간주됩니다.

측정: 채굴자 보상 = 검증된 데이터 포인트 수 × 단위 데이터 포인트 가격. 유효하지 않은 데이터 포인트는 보상이 없으며 평판이 감소합니다.

6.6 중재

분쟁은 중재 계약에서 처리됩니다. 여러 중재자(고지분 검증자)가 독립적으로 판단하고 투표합니다. 과반수 결정이 우선합니다.

7. 분산 학습 통합

학습 작업은 EtherFLOP 프레임워크에 통합됩니다. 사용자는 기준 모델 CID, 데이터셋 CID, 학습 구성을 지정합니다. expectedEFLOPS는 총 최적화 단계 수 × 단계당 FLOPs로 계산됩니다.

노드는 주기적인 체크포인트 해시와 그래디언트 중간값을 제출합니다. 검증자는 무작위 체크포인트를 재실행하여 실제 실행을 확인합니다. 학습 후, 검증자는 공개 테스트 세트에서 모델 성능을 평가합니다. 개선 목표를 달성하지 못하면 부분적인 지분 슬래싱이 발생합니다.

8. 보안 및 프라이버시

  • 측정 보안: 앵커 모델과 오라클 위원회는 EFLOPs를 조작 불가능하게 만듭니다. ZK 증명은 신뢰 없는 측정을 제공합니다.
  • 시빌 방어: 높은 스테이킹과 평판에 따라 확장되는 작업 한도.
  • 프라이버시: 추론 입력은 TEE 내에서 복호화됩니다. 증류 프롬프트는 프록시 네트워크를 통해 양파 암호화됩니다.
  • 검열 저항: 모든 계약은 업그레이드 불가능하거나 DAO가 제어합니다. 프록시 네트워크는 libp2p 노이즈 암호화로 분산됩니다.

10. 결론

Ethercoin의 기술 아키텍처는 유용한 연산의 검증 가능한 측정에 중점을 둡니다. EtherFLOP 단위, 계층형 증명, 랜덤 앵커, ZK/TEE 검증, 포괄적인 부정행위 방지 매트릭스를 통해 네트워크는 신뢰할 수 없는 환경에서 AI 컴퓨팅의 공정하고 안전한 거래를 가능하게 합니다. 증류 프로토콜은 이 컴퓨팅 마켓을 지식 해방을 위한 도구로 확장합니다.
